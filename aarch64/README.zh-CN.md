# llm.asm 的 AArch64 移植版（Cortex-A76 / Cortex-A55）

[English](README.md) · [Русский](README.ru.md) · **简体中文**

本项目用 GNU `as` 和 `ld` 从零编写，把 [llm.asm](https://github.com/alesha-pro/llm.asm) 的 Linux 推理引擎（Qwen3-0.6B Q8_0）移植到 AArch64 汇编：不使用 C，不依赖 libc，生成 17 KB 的静态 ELF（`build/asm-llm-arm64`）。模型文件（`.asmbin` v2）、对话模板、分词器和输出格式与 x86-64 版本相同。

## 与 x86-64 代码的区别

- `sdot`（ARMv8.2 点积指令）直接对有符号字节做乘法，不再需要 x86 版本中的符号技巧。
- 加载时对权重重新排布：每 4 行按 4 字节一组交错存放，思路与 llama.cpp 的 `q8_0_4x4` 相同。这样一条按元素的 `sdot` 就能同时计算 4 行，x 每 4 行只加载一次。重排后的副本保持文件中的偏移不变。`--norepack` 切换为普通的按行内核。
- 内核有两个版本：Cortex-A76 使用带软件预取的版本，Cortex-A55 使用不带预取的版本——对这种顺序执行的核心，预取会损失约 35% 的性能。每个线程固定在 `taskset` 掩码中的一个 CPU 上，并读取 `MIDR_EL1` 选择版本。负责全部串行工作的主线程总是放在大核上。
- 动态分配工作：线程用 LSE `ldadd` 领取 16 行一块的任务，快的核心领得更多。结果与哪个线程计算哪一行无关。
- 线程通过 `ldaxr` + `wfe` 等待。
- 重排后的权重默认放在 2 MiB 透明大页上（`madvise`）；`--nohugepages` 可关闭。
- 未移植：交互式对话、采样（只支持贪心解码）、裸机操作系统和 `FAST_Q8=0`。

## 正确性

- 在 1×A76、4×A76、1×A55、4×A55 和全部 8 个核心上，logits 和输出文本逐位一致。
- 与 x86-64 版本相比，预填充后 logits 的余弦相似度为 0.99971。两个 x86-64 版本彼此之间也相差同样的量级（0.99970）。64 个贪心解码 token 中前 15 个与 x86-64 输出一致，之后出现近似平局：该步有四个候选彼此相差不到 0.23。

## 测试结果

开发板：FriendlyElec CM3588 Plus（RK3588：4× Cortex-A76 2.3 GHz + 4× Cortex-A55 1.8 GHz，32 GB LPDDR4X），Debian 12，内核 6.1。模型 Qwen3-0.6B Q8_0，提示词 34 个 token，生成 64 个 token，测 3 次。llama.cpp b12810 在板上本机编译（`-mcpu=cortex-a76.cortex-a55`、dotprod、OpenMP），用 `llama-bench` 测量。用 `taskset` 选择核心：cpu0–3 为 A55，cpu4–7 为 A76。

生成速度（token/秒），分别为开发板默认的 DDR 调频策略（`dmc_ondemand`）和 DDR 固定在 2400 MHz 时的结果（`results/*.csv`）：

| 核心 | 本移植版，默认 | llama.cpp，默认 | 本移植版，DDR 固定 | llama.cpp，DDR 固定 |
|---|---:|---:|---:|---:|
| 1×A76 | 19.7 | 23.0 | 19.6 | 22.7 |
| 2×A76 | 28.0 | 31.5 | 28.1 | 31.6 |
| 4×A76 | **34.3** | 30.5 | **32.7** | 30.7 |
| 1×A55 | 3.0 | 4.8 | 4.5 | 5.7 |
| 2×A55 | 3.5 | 9.7 | 6.2 | 10.0 |
| 4×A55 | 10.3 | 16.0 | 11.0 | 16.1 |
| 全部 8 个 | 28.6 | 19.6 | 28.8 | 22.1 |

DDR 固定时的预填充速度（token/秒）：本移植版在 1 / 2 / 4 个 A76 上为 26.8 / 37.8 / 44.6，在 1 / 2 / 4 个 A55 上为 6.1 / 8.5 / 14.8，全部 8 个核心为 35.5；llama.cpp 分别为 64.4 / 125.8 / 227.7、14.3 / 28.5 / 56.0 和 156.8。

## 结论

- **大核。** 在 1–2 个 A76 上 llama.cpp 快 12–16%；在 4 个 A76 上本移植版快 7–12%：此时瓶颈是内存带宽，较低的同步开销开始发挥作用。4 个 A76 上的 34 token/秒是这块开发板上的最佳成绩。
- **小核。** DDR 固定时，llama.cpp 在 A55 上快 1.3–1.6 倍。
- **内存频率。** 在默认调频策略下，只有 A55 工作时内存停留在 534 MHz；只要有一个 A76 工作，内存就升到 2400 MHz。因此默认情况下只用 A55 的任务内存带宽不足：固定 DDR 后，本移植版在单个 A55 上提速 49%。
- **大小核混用。** 在 4 个 A76 之外再加上 A55，两个引擎都会变慢，因为内存带宽已经饱和。请使用 4 个大核：在允许使用全部核心时，`-t 4` 会自动选择 A76。
- **预填充**改为批处理：矩阵乘法使用寄存器分块内核，注意力每层只派发一次任务，逐 token 步骤分配到各线程。在 4×A76 上，227 个 token 的提示词比 llama.cpp 快 2%；其他情况下 llama.cpp 的速度是本移植版的 1.04–1.31 倍（逐 token 预填充时为 2.3–5 倍）。

## Ollama 与两个操作系统同时运行

Ollama 0.32.5 在独立实例中使用同一个 Q8_0 GGUF 文件，速度取自它自己的 `eval_count` / `eval_duration`。主机上的生成速度（token/秒），每次测量前 SoC 都先冷却到 70 °C 以下（`results/three-engines-host.csv`）：

| 核心 | 本移植版 | llama.cpp | Ollama |
|---|---:|---:|---:|
| 1×A76 | 19.5 | 23.0 | 22.0 |
| 4×A76 | **34.2** | 29.8 | 29.0 |
| 1×A55 | 3.0 | 4.9 | 4.4 |
| 4×A55 | 10.3 | 15.8 | 13.3 |
| 全部 8 个 | 28.0 | 22.9 | 22.2 |

同时运行两个 KVM 虚拟机（QEMU 运行在 Docker 中，每个虚拟机都是 initramfs 中的最小 Linux），一个固定在四个 A76 上，另一个固定在四个 A55 上（`vm/`、`results/vm/`）。生成速度中位数（token/秒）：

| | A76 虚拟机 | A55 虚拟机 | 合计 |
|---|---:|---:|---:|
| 本移植版，各自单独运行 | 34.2 | 10.0 | — |
| 本移植版，同时运行 | 21.7 | 6.0 | 27.7 |
| Ollama，各自单独运行 | 28.0 | 12.7 | — |
| Ollama，同时运行 | 18.8 | 7.4 | 26.2 |

两个虚拟机同时运行的总速度低于单独运行的 A76 虚拟机。最初几秒内，A76 虚拟机在满频下就从 30 降到 22 token/秒，因为两个集群共享 DDR 内存和 L3 缓存。一分钟内 SoC 升温到 85 °C，A76 降频到 1.8–2.0 GHz，A55 降频到 1.2 GHz。虚拟化本身几乎没有开销：虚拟机内 34.2 token/秒，主机上 34.3。

## 自动选择线程数与 Qwen3-1.7B

不指定 `-t` 时，引擎为 `taskset` 掩码中的每个大核启动一个线程；如果掩码中只有 A55，则为每个允许的核心启动一个线程。因此在整块开发板上直接运行时，引擎会自动使用四个 A76：34.4 token/秒，而用全部 8 个核心只有 28.6。只要有大核参与，任务块为 16 行；只用 A55 时为 256 行：4×A55 上从 10.3 提升到 12.8 token/秒。`--chunk-shift n` 可设置 2^n 行，用于实验。

Qwen3-1.7B Q8_0 的生成速度（token/秒），测试方法同上：

| 核心 | 本移植版 | llama.cpp | Ollama |
|---|---:|---:|---:|
| 1×A76 | 7.1 | 8.4 | 8.6 |
| 4×A76 | **11.7** | 10.8 | 11.1 |
| 4×A55 | 5.3 | 6.4 | 6.0 |

## 批量预填充

与 x86-64 版本相同的方案，默认每批 16 个 token。每批使用重排权重上的“4 行 × 2 个 token”寄存器分块内核：每个块的权重寄存器同时服务两个 token，因此每个 token 从 L1 读取该行组的次数减半。对每个 token，int32 SDOT 求和是精确的，浮点步骤与单 token 内核相同，因此在任意核心组合上，logits 都与逐 token 预填充逐位一致。

单独测试内核，数据位于 L1（`aarch64/kbench.s`），每行、每个 token、每个 32 值块的周期数：A76 为 1.93（之前 2.35），A55 为 8.1（之前 11.0）。

每批的注意力在每层只作为一个线程池任务派发：每个任务块是同一 token 的两个 query 头，它们读取同一个 kv 头。注意力分数一次计算 2 个头 × 2 个位置，使用 16 个累加器，其布局和归约顺序与单 token 点积相同，因此每次加载 q 和 K 都用于两次乘法。两个头的每个 32 值输出块在所有位置上都保留在寄存器中，而不是每个位置都从内存读写一次输出。同一对头的任务块连续排列，因此其 K 和 V 行在 token 之间一直留在核心的 512 KB L2 中；按“先 token”顺序时，同一内核在单个 A76 上没有任何提升。logits 仍然逐位一致。

在矩阵乘法批次之间，残差加法、RMSNorm、激活量化、QK 归一化、RoPE、写入 KV 缓存和 SwiGLU 也作为线程池任务执行，每个任务块处理一个 token（SwiGLU 为四分之一个 token），注意力任务则直接量化自己的输出，供输出投影使用。每个任务块执行的都是单 token 代码，因此 logits 仍然逐位一致。

预填充速度，Qwen3-0.6B，token/秒（各 3 次，每次在温度低于 65 °C 时开始；llama.cpp 同上，`llama-bench -p 34,227`；`results/prefill-tiles.txt`、`results/prefill-attention.txt`、`results/prefill-steps.txt`）：

| 核心 | 34 个 token：逐个 | 34 个 token：批量 | 34 个 token：llama.cpp | 227 个 token：批量 | 227 个 token：llama.cpp |
|---|---:|---:|---:|---:|---:|
| 4×A76 | 45 | 179–190 | 213 | 210–220 | 206 |
| 1×A76 | 27 | 55–61 | 60 | 53–54 | 57 |
| 4×A55 | 13 | 40–41 | 53 | 41–42 | 52 |

与上一版交替运行对比，把逐 token 步骤交给线程池后，227 个 token 的提示词在 4×A76 上提升 9%（194 → 211 token/秒），在 4×A55 上提升 7%（39.0 → 41.8）；34 个 token 的提示词分别提升 6% 和 3%；单个 A76 上的差异在 1% 以内。在此之前，批量注意力在 227 个 token 的提示词上提升了 8–11%（4×A76：179 → 202 token/秒）。第一版批量预填充（每次处理一组 4 行和一个 token）在 34 个 token 的提示词上为 150 / 47 / 29.5 token/秒，在 227 个 token 上为 157 / 43 / 27.8。

剩余差距（227 个 token 的提示词）：在 1×A76 上，注意力占 4.3 秒中的 0.44 秒（批量注意力之前为 0.83 秒），其中分数约 0.13 秒，softmax 约 0.06 秒，V 的加权求和约 0.25 秒，而这部分时间有一半在等待从 L2 读取 V 行。在 4×A76 上约占 1.07 秒中的 0.15 秒。逐 token 步骤在 4×A76 上占 1.07 秒中的 0.11 秒（之前单线程为 0.20 秒），在 4×A55 上占 5.4 秒中的 0.38 秒（之前为 0.82 秒）。在四个 A76 上，这些步骤的耗时与单个 A76 上几乎相同，这说明时间主要花在核心之间搬运 token 行：矩阵乘法由所有核心共同写出每个 token 行，而每个步骤要在一个核心上读取整行。

## 构建与运行

```bash
aarch64/build.sh                     # 在 AArch64 Linux 机器上（GNU as + ld）
taskset -c 4-7 build/asm-llm-arm64 -m models/qwen3-0.6b-q8_0.asmbin -p "..." -n 64 -t 4
aarch64/bench_cores.sh build/asm-llm-arm64 <model.asmbin> <llama-bench> <model.gguf> 3 out.csv
(cd aarch64 && as -o ../build/kbench.o kbench.s && ld -static -o ../build/kbench ../build/kbench.o ../build/aarch64/matmul.o)
taskset -c 4 python3 aarch64/kbench.py build/kbench 1   # A76 上的内核周期数；A55 用 cpu0 和 0
```

模型文件与 x86-64 版本相同，都是 `.asmbin` v2（`scripts/export_weights.py --scale-dtype fp16`）。
